## How to interpret the reported results

The CSV files in `results/` are transcriptions of the manuscript, **not measurements generated by this repository update**. Missing metrics are blank, not zero. Each row records its source table. Quality, validation, checkpoint-selection and runtime experiments must remain separate.

## Runtime protocol (Tables XV-XIX)

- NVIDIA RTX 3070 **desktop GPU**, 228 images; AMP where supported; output disk writing disabled.
- Single-image means batch size 1. Batch size for the batch-enabled table is not specified in Table XV; it must be recovered from the original benchmark logs before exact reproduction.
- Model-only: tensors are already prepared. For TinyCurveNet this is **parameter prediction only**, not a completed enhanced image. For AquaFastNet and EdgeOSA it produces the dense image.
- Standard pipeline: loading, resizing, preprocessing, GPU transfer and inference; TinyCurveNet also applies the deterministic transformation.
- Optimized pipeline: pre-resized target-resolution inputs. Table XIX gives single-image timings; Table XVII gives batch-enabled per-image timings.
- In particular, **4.95 / 12.11 / 53.85 ms are batch-optimized timings**, not single-image latency. EdgeOSA's optimized single rate is **21.68 FPS**, not 61.68 FPS.
- Exact inference resolution, preprocessing, checkpoint, batch size, precision, warmup, synchronization and timing boundaries must be logged for any new benchmark. The paper notes that public implementations use different resolutions, so its runtime ranking is implementation-level rather than architecture-normalized.
- Jetson/embedded validation, energy measurements and downstream detection, matching or SLAM benefits are future work. Demo utilities do not establish those results.

## Datasets, splits and metrics

The paper uses paired UIEB/EUVP and no-reference datasets/subsets including UIEB-C60, EUVP-T515, SQUID-T16, RUIE-T78 and U45. Keep the Table V label **UIEB test subset**; do not relabel its scores as all 890 paired images. Some ablation prose separately refers to UIEB paired-890.

The manuscript describes EUVP's 515 pairs as validation samples as well as reporting EUVP Test scores. Therefore the split manifests and checkpoint-selection history must be checked before claiming an untouched test set. Existing absolute paths in repository manifests must be remapped to local data; datasets are not bundled. Check image identity overlap across train, validation and test (including pseudo-pairs).

PSNR, SSIM and MS-SSIM: higher is better. LPIPS and NIQE: lower is better. UIQM/UCIQE: higher is better within the same implementation. Tables V and XIII use different reported scales; do not merge or rank them against literature implementations. Table XIV is a separate no-reference evaluation and its NIQE values are not interchangeable with Table V.

Training uses RGB tensors in [0,1]. Dense-model composite loss is L1 + 0.20 × SSIM-loss + 0.05 × **VGG16 feature loss**. TinyCurveNet's corrected composite is L1 + 0.20 × (1-SSIM) + 0.05 × **LPIPS(VGG)**. These perceptual objectives are not the same. L1-only and MSE-only are separate training variants, not switches to apply to a trained checkpoint and relabel its scores.

## Reproducibility gaps discovered in the released code

| Model | Current default model parameter count (CPU audit) | Paper ablation parameter count |
|---|---:|---:|
| TinyCurveNet-CCM | 11,642 | Not given in Tables XXI/XXV; 18 denotes predicted values, not trainable weights |
| AquaFastNet, base=32 | 309,862 | 107,670 (Table XXIII) |
| EdgeOSA, base=32, four stages, three blocks/stage | 43,479 | 46,055 (Table XXIV) |

Bundled checkpoints load strictly into these current architectures. The exact code/checkpoints that produced the different paper counts are needed to reconcile them; changing channel widths just to match a count would invalidate existing weights. Architecture tensor shapes and pretrained files have consequently been preserved.

TinyCurveNet's Anticast/Polish checkpoint names from Table XXII are not present under those names in the repository. The supplied stage/example weights are not certified substitutes. AquaFastNet's `runs/uie_fastunet_base32/best.pt` records validation manifest `bench_euvp_test515.csv` and best PSNR 25.2686; that metadata alone does not establish the UIEB provenance of the similarly valued manuscript row. EdgeOSA's bundled best checkpoint records epoch 1031 and best validation PSNR 24.3409; this is not a rerun of its paper evaluation.

TinyCurveNet's old progressive trainer detached SSIM/LPIPS values, making their gradients zero. Its compatibility entry point now uses the corrected trainer; select `loss.objective: l1` for an explicit L1-only experiment. Its paired augmentation now shares a random crop/flip between input and target; the previous independent flips could misalign pairs. These training corrections do not retroactively change the provenance or measured quality of existing weights.

Legacy metric scripts are retained for provenance and may implement approximations (including NIQE fallbacks and internal-scale UIQM/UCIQE). Do not report proxy/fallback scores as canonical metrics. Pin the exact metric library/version, LPIPS backbone, image size, RGB range and averaging protocol when reproducing the paper. The manuscript also has differing EdgeOSA MSE MS-SSIM entries across tables; no unreported value is filled into Table V's blank.
